# AI Jira QA Copilot v2

> Turn any Jira ticket into Android / iOS / Web QA test cases — grounded in your real GitHub repo, generated by your preferred LLM. Pluggable providers, ready to evolve into a SaaS.

Live demo of v1: [jiraqa.com](https://jiraqa.com) · v1 repo: [asif786ka/asif-ai-jira-qa-copilot](https://github.com/asif786ka/asif-ai-jira-qa-copilot)

## What it does

You point the app at a real Jira project and a real GitHub repo. It pulls the ticket details, scrapes a curated snippet of the repo (README + file tree + key config files), auto-detects whether the codebase is Android, iOS or Web, and asks an LLM to produce 3–8 structured test cases tailored to that platform's testing framework (Espresso, XCUITest, or Playwright). Output is validated against a Zod schema, so what you get back is always well-formed JSON ready to drop into your test management system.

## Quick start

You need:

- **Node 20+** ([nodejs.org](https://nodejs.org))
- **pnpm 9** (`npm install -g pnpm@9`)
- **Python 3.12+** ([python.org](https://www.python.org/downloads/)) — only if you want the Python backend; TypeScript-only works without it

Then:

```bash
git clone https://github.com/asif786ka/asif-ai-jira-qa-copilot-v2.git
cd asif-ai-jira-qa-copilot-v2

# One command — installs deps, bootstraps .env.local, starts both backends:
./run-dev.sh
```

The script will create `apps/web/.env.local` from the template on first run and auto-generate a `SESSION_SECRET`. You'll need to add your LLM API key to that file before you can generate. See the next section.

Open **http://localhost:3000**.

## How to get the tokens you need

You'll connect 4 things. Three are required, one is optional.

**OpenAI API key** (required if you want OpenAI). Sign in at [platform.openai.com/api-keys](https://platform.openai.com/api-keys), click "Create new secret key", give it the name "jiraqa-dev", copy the `sk-...` value. Paste into `OPENAI_API_KEY` in `apps/web/.env.local`. Costs about $0.002 per generation on GPT-4o-mini.

**Google Gemini API key** (alternative to OpenAI). Go to [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey), click "Create API key", copy the `AIzaSy...` value. Paste into `GEMINI_API_KEY`. Has a generous free tier — great for development. Costs ~$0.008 per generation on Gemini 2.5 Flash if you exceed the free tier.

**Jira API token** (required to read your Jira tickets). Sign in to [id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens), click "Create API token", label it "JiraQA Copilot". This goes into the **Connections page in the UI** (not the .env file) along with your Jira site URL (e.g. `acme.atlassian.net`) and email.

**GitHub fine-grained Personal Access Token** (required to read your repo). At [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new), pick your repos, grant **Repository permissions → Contents: Read** and **Metadata: Read**, and copy the `github_pat_...` value. This goes into the **Connections page in the UI**.

The first two go in `apps/web/.env.local` (and stay on your machine). The last two go through the UI, get encrypted, and end up in an HttpOnly session cookie. None of these are ever logged, persisted to disk in plaintext, or sent anywhere except their respective APIs.

## After it boots: the 3-step wizard

After `./run-dev.sh` shows `✓ Ready` and you open http://localhost:3000:

1. Click **Connect Jira + GitHub** in the header → paste your Jira credentials and GitHub PAT → click **Test** on each, then **Save**.
2. Back on the home page, pick a **Project** then an **Issue** from your Jira. The ticket preview appears below.
3. Pick a **GitHub repo**. The wizard auto-detects platform from your code (`AndroidManifest.xml` → Android, `*.xcodeproj` / `Podfile` → iOS, `package.json` + framework → Web). Override the detected platform with the buttons if needed.
4. Click **Generate test cases**. 3–8 test cases stream in as cards, each with priority badge, automation hint (Espresso / XCUITest / Playwright), preconditions, steps, expected result, and tags.

The header has two toggles that change runtime behaviour without re-deploying: provider (OpenAI ↔ Gemini) and backend (TypeScript ↔ Python).

## Adding a new LLM provider

The whole point of the provider abstraction is that adding Anthropic, Mistral, or a local Ollama model is one new file and one line of registration. The interface is 4 methods:

```ts
// packages/providers/src/llm/types.ts
export interface LLMProvider {
  readonly name: string;
  readonly defaultModel: string;
  isAvailable(): boolean;
  complete(req: LLMCompletionRequest): Promise<LLMCompletionResponse>;
}
```

Implement it, then register:

```ts
// packages/providers/src/llm/registry.ts
registerLLMProvider("anthropic", () => new AnthropicProvider());
```

The Python sidecar mirrors the exact same pattern in `apps/api-python/api/llm.py`. Subclass `LLMProvider`, call `register_llm_provider(...)`, done.

## Deploy to Vercel

```bash
npm i -g vercel
vercel link
vercel env add SESSION_SECRET    # paste: openssl rand -base64 32
vercel env add OPENAI_API_KEY
vercel env add GEMINI_API_KEY
vercel --prod
```

Vercel auto-detects:
- The Next.js app at `apps/web` (from `vercel.json`)
- The Python function at `api/python.py` (rewritten from `/pyapi/*` → `/api/python`)

Both run on the same domain — single-origin SaaS, no CORS, no separate hosts. The BackendSwitcher in the header flips between `/api/*` (TypeScript) and `/pyapi/*` (Python) at runtime.

## Troubleshooting

**"API key not valid"** — your `.env.local` has stale keys. Re-copy: `cp .env.example apps/web/.env.local`, then put your real keys in `apps/web/.env.local`. **Restart the dev server** (Ctrl-C + `./run-dev.sh`) — Next.js only reads env vars on boot.

**Jira issues dropdown empty** — your Jira instance might still be on the deprecated `/rest/api/3/search` endpoint. The provider falls back to it automatically; if you still see nothing, check that the project actually has issues you have read access to.

**"Module not found" build errors** — clear dangling state and re-install: `rm -rf node_modules apps/web/node_modules packages/*/node_modules && ./run-dev.sh`.

**Provider shown in header doesn't match the error message** — fixed: the switcher now syncs to the server cookie on mount, not just on click. If you upgraded, refresh the browser tab once.

## SaaS roadmap

The architecture is built for evolution from a single-user demo into a multi-tenant subscription product. Roughly in this order:

- **Stripe + accounts** — NextAuth/Clerk for sign-in, per-user encrypted token storage, plan-gated `/api/generate`, hard rate limits to prevent abuse.
- **Tier 2 OAuth** — Atlassian OAuth 2.0 (3LO) for Jira Cloud and GitHub App or OAuth App for GitHub. Same UI surface, just an OAuth button instead of paste-token.
- **Test case history** — Vercel Postgres `runs(id, user_id, ticket_key, platform, provider, output_json)` so users see and re-export past runs.
- **Push back to Jira** — create sub-tasks or attach Markdown/Gherkin to the original ticket.
- **BYOK + self-host** — let enterprise customers use their own Azure OpenAI / AWS Bedrock keys, or run the whole stack as a Docker image inside their VPC.
